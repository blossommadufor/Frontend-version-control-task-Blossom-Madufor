Version Control Deliverable (Steps 1 – 5)

Step 1: Repository Setup

To lay the foundation for version control, I set up a public repository on GitHub to manage source code and maintain transparency.

  • Repository Initialization: Created a public repository titled Frontend-version-control-task-[yourname] on GitHub.
  • Documentation: Generated an initial README.md describing the project's purpose and setup.
  • Local Workspace Setup: Cloned the remote repository locally using git clone.

Step 2: Branching & Collaboration Strategy

To ensure code quality and isolate feature development from the production codebase (main), I used a feature-branch workflow with atomic commits.

Feature Branch 1: feature-header

  • Created and switched to the branch via git checkout -b feature-header.
  • Commit 1: feat: create initial HTML structure and header tag
  • Commit 2: feat: add navigation links to header
  • Commit 3: style: apply layout and color styling to header
  • Pushed to GitHub using git push -u origin feature-header.

Feature Branch 2: feature-footer

  • Switched back to main and isolated the footer work via git checkout -b feature-footer.
  • Commit 1: feat: add basic footer container and copyright notice
  • Commit 2: feat: include social media links in footer
  • Commit 3: style: add responsive dark styles for footer
  • Pushed to GitHub using git push -u origin feature-footer.

Step 3: Pull Requests, Code Review, & Merging

With feature branches published upstream, I managed integration into main using Pull Requests (PRs) to simulate team collaboration.

  • Pull Request Creation: Opened distinct PRs for both feature-header and feature-footer targeted at main.
  • Code Review Simulation: Examined line-by-line diffs under the Files changed tab and added review comments.
  • Merge Conflict Resolution: Resolved cross-branch stylesheet reference conflicts directly on GitHub.
  • Final Integration: Executed the formal merge sequence on GitHub for both feature branches.

Step 4: Reversion & Branch Management

Demonstrated emergency recovery protocols and branch maintenance workflows to keep repository records organized.

  • Commit Reversion (git revert): Intentionally introduced an unneeded paragraph element to main, committed it, and executed git revert HEAD --no-edit to create an inverse commit that safely restored the file.
  • Branch Renaming: Created temp-sidebar-branch locally and renamed it to feature-sidebar using git branch -m, followed by upstream synchronization via git push -u and git fetch --all.

Step 5: Final Documentation & Delivery

Finalized all project assets, structured comprehensive markdown logs, and verified end-to-end repository setup.

  • Created a local screenshots/ directory containing visual proof of merged Pull Requests.
  • Updated README.md with branching tables, CLI reference commands, and core workflow lessons learned.
  • Committed and pushed the complete deliverable directly to the production branch.
